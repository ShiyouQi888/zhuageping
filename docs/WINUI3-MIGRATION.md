# Windows App SDK Migration Plan

## Decision

Build a separate C#/.NET WinUI 3 shell and migrate feature-by-feature. Keep the Electron release as the supported baseline until the native build passes parity and packaging gates. Reuse the existing C# recorder host first; move business logic only when a migration has a measurable benefit. Windows App SDK modernizes the app shell and Windows integration, but does not itself fix capture quality, frame pacing, or audio bugs.

## Phases and gates

| Phase | Scope | Exit gate |
| --- | --- | --- |
| 0. Baseline | Inventory Electron IPC, settings schema, shortcuts, capture/recording flows, dependencies, and known regressions. Preserve the current installer and release workflow. | Feature/behavior checklist and rollback artifact recorded. |
| 1. Native spike | WinUI shell prototype; monitor enumeration and physical bounds; border windows with topmost, no-activate, click-through, and capture-exclusion flags; multi-monitor/DPI and taskbar checks. | On supported Windows builds, all connected displays are selectable, border tracks the correct monitor, never steals input, and capture tests prove it is excluded in each intended backend. Failure blocks migration of the affected overlay workflow. |
| 2. App shell | Main settings window, navigation, preferences persistence, tray, startup, diagnostics, update strategy. | Existing configuration survives upgrade; shortcut and tray regression checklist passes. |
| 3. Screenshot | Region/full-screen/scroll capture, annotation, color picker, OCR, pinning, output/history. | Feature parity for common workflows; multi-monitor, mixed DPI, clipboard and cancellation checks pass. |
| 4. Recording | Reuse RecorderHost; integrate start/pause/resume/stop, display/region selection, audio, output and recovery. Change capture backend only behind a measured prototype. | Long-duration and repeated start/stop runs create playable files with correct bounds/audio and responsive controls; no overlay in output. |
| 5. Distribution | MSIX and direct-download installer, dependencies/runtime, signing, update feed, data migration, staged rollout. | Clean-machine install/upgrade/uninstall and rollback verified; OCR assets and all native dependencies are present. |

## Implementation rules

- Keep the prototype isolated in `native/winui-shell`; do not route production shortcuts to it until phase 2.
- Preserve settings compatibility; write an explicit migration and backup before changing schemas.
- Keep native overlay/window interop behind small services so HWND styles and capture behavior can be tested independently of page layout.
- Treat `WDA_EXCLUDEFROMCAPTURE` as backend- and OS-dependent until verified with actual Windows Graphics Capture and recorder outputs. A successful API call alone is not acceptance.
- Capture the full monitor `OuterBounds` for full-display recording, not only its work area; account for negative virtual-desktop coordinates and per-monitor DPI.
- No production cutover until each feature has a documented pass/fail checklist. Keep the previous installer available for rollback.

## Rollback

The existing Electron application remains unchanged and independently buildable throughout the migration. Release the native app as an opt-in preview first. If a gate fails, stop at that phase and continue distributing the Electron version; do not overwrite its update channel or user data. Rollback must include restoring the prior installer/update metadata and preserving user-created captures and settings.

## Initial prototype

`native/winui-shell` is a technical spike, not a replacement application. Its first harness enumerates displays and draws a four-edge test frame. Validate visually and with recorded test output on each target Windows version, display layout, scaling factor, and capture backend before treating capture exclusion as proven.
